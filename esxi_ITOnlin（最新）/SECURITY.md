# 安全说明

## 安全最佳实践

### 1. 配置安全

#### 敏感信息保护
- **不要将敏感配置硬编码**在代码中
- 使用环境变量或配置文件管理敏感信息（如密码、密钥）
- `.env` 文件已包含在 `.gitignore` 中，确保不会被提交到版本控制

#### 示例配置
```bash
# .env 文件示例
DATABASE_URL=mysql+pymysql://user:password@host:port/database
ESXI_PASSWORD=your_esxi_password
SECRET_KEY=your-secret-key-change-in-production
```

### 2. API安全

#### 认证与授权
- 当前版本未内置认证机制，建议在生产环境中添加
- 推荐使用 OAuth2 或 API Key 认证
- 限制API访问频率，防止暴力攻击

#### HTTPS
- 生产环境必须使用HTTPS
- 配置SSL/TLS证书
- 可使用Nginx或其他反向代理处理SSL终止

### 3. 数据安全

#### 数据库安全
- 使用参数化查询防止SQL注入
- 最小权限原则：数据库用户只授予必要的权限
- 定期备份数据库

#### 数据传输
- 敏感数据传输使用加密
- 日志中不记录密码等敏感信息

### 4. 容器安全

#### 镜像安全
- 使用官方基础镜像
- 定期更新镜像以修复安全漏洞
- 避免在镜像中存储敏感信息

#### 容器运行
- 避免以root用户运行容器
- 限制容器的网络访问权限
- 使用Docker网络隔离

### 5. 日志安全

- 日志中不包含敏感信息（密码、密钥等）
- 设置适当的日志级别
- 定期清理日志文件

### 6. 漏洞报告

如果你发现安全漏洞，请通过以下方式报告：

1. **创建安全Issue**：在GitHub上创建Issue，标记为`security`标签
2. **发送邮件**：发送详细描述到项目维护者邮箱
3. **提供详细信息**：
   - 漏洞类型
   - 影响范围
   - 复现步骤
   - 建议修复方案

### 安全更新

项目维护者承诺：
- 及时响应安全漏洞报告
- 在合理时间内发布安全修复
- 提供安全更新公告
