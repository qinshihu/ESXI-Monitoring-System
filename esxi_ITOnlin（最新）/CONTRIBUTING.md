# 贡献指南

欢迎贡献代码！请阅读以下指南，确保你的贡献符合项目标准。

## 代码规范

### Python代码规范
- 遵循 [PEP 8](https://peps.python.org/pep-0008/) 规范
- 使用 `black` 进行代码格式化
- 使用 `flake8` 进行代码检查
- 使用 `isort` 整理import顺序

### 提交信息规范
提交信息应遵循以下格式：
```
<类型>: <简短描述>

<详细描述（可选）>
```

类型说明：
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码风格调整（不影响代码功能）
- `refactor`: 重构代码
- `test`: 测试代码
- `chore`: 构建/工具相关

示例：
```
feat: 添加虚拟机网络流量告警功能

- 新增虚拟机网络指标采集
- 添加网络流量告警阈值配置
- 完善API响应模型
```

## 开发流程

1. **Fork 仓库**
2. **创建分支**：根据功能类型创建分支
   - `feature/*`: 新功能
   - `bugfix/*`: 修复bug
   - `hotfix/*`: 紧急修复
   - `docs/*`: 文档更新
3. **编写代码**：实现功能或修复问题
4. **编写测试**：确保新增代码有测试覆盖
5. **运行测试**：确保所有测试通过
6. **提交代码**：推送分支到你的fork
7. **创建Pull Request**：提交到主仓库

## 测试指南

### 运行测试
```bash
# 安装测试依赖
pip install pytest pytest-asyncio httpx

# 运行所有测试
pytest

# 运行特定测试文件
pytest tests/test_api.py

# 生成测试覆盖率报告
pytest --cov=app --cov-report=html
```

### 测试规范
- 单元测试应放在 `tests/` 目录下
- 测试文件命名格式：`test_*.py`
- 使用 `pytest` 框架
- 确保测试可独立运行

## PR检查清单

在提交PR前，请确保：

- [ ] 代码符合PEP 8规范
- [ ] 已通过所有测试
- [ ] 新增功能有对应的测试覆盖
- [ ] 文档已更新（如有需要）
- [ ] 提交信息清晰规范
- [ ] 没有未使用的导入
- [ ] 没有调试代码（print, debugger等）

## 问题报告

如果你发现bug或有功能建议，请创建Issue并提供以下信息：

1. **环境信息**
   - Python版本
   - 操作系统
   - 相关依赖版本

2. **问题描述**
   - 清晰描述问题现象
   - 提供复现步骤
   - 如果可能，提供错误日志

3. **期望行为**
   - 描述你期望的正确行为
